01

WHAT IT ACTUALLY MEANS

这句 From → To 到底是什么意思？

不是两个口号，而是交付物、人的角色、系统权限与价值衡量同时发生迁移。

比较维度过去更看重现在更看重为什么重要
交付物答案、建议、草稿一项完成且可验收的工作

价值单位从一次互动，变成一项有开始、结束和结果的任务。

人的角色人逐步操作，AI 辅助人授权、审批并处理异常

人没有消失，而是从执行者变成边界设定者和结果审查者。

系统权限读取信息、生成内容在权限范围内执行并写回

Agent 开始触碰真实业务系统，因此 audit、rollback 与权限控制变成产品本体。

价值衡量使用量、对话数、Demo 效果完成率、可靠性、ROI

“用了多少”不再充分，客户开始追问“完成了什么、是否值得付费”。

02

CLAIM → ACTION → PROOF → GAP

为什么我们这样判断？

同一项子判断横向看：市场怎么说、真实做了什么、经营上看见了什么、还缺什么。

Agent 会从建议工具变成工作执行者

市场观点

OpenAI 将新的工作单位描述为可跨工具、跨时间运行的 delegated task。

已观察行动

GitHub 把人的角色改写为管理 agent output、检查重要变更。

经营验证

Canary 已把 Agent 放进酒店销售从 inquiry 到 booking 的流程。

仍未证明

长期使用中的完成率、客诉、续费与单位经济性。

越接近真实系统，越需要受限自治

市场观点

Mews 强调 system context、evals 和 guarded action。

已观察行动

Oracle 把 AI 嵌进 OPERA Cloud 现有操作流，而非另起一个聊天入口。

经营验证

行业产品已开始围绕审批、写回和真实流程设计。

仍未证明

哪些动作可以无人审批，以及出错后的责任如何分配。

03

WHAT CHANGED · 30D

过去 30 天，判断具体怎样变化？

不是一个抽象的 Pulse 标签，而是一份可以检查的变化账本。

  1. 此前判断

    Agent 机会主要被讨论为模型能力、长任务和 Copilot 界面升级。

  2. 新增支持

    过去 30 天新增了酒店垂直 Agent、PMS 内嵌 AI、具名 VC 投资以及 trajectory monitoring 四类信号。

  3. 新增挑战

    OpenAI 的 long-horizon 安全研究显示，持续执行会产生静态评估捕捉不到的失败，需要干预与回滚。

  4. 当前结论

    结论没有反转：Agent 正走向工作交付；但市场收敛的是 bounded autonomy，不是无限自治。
